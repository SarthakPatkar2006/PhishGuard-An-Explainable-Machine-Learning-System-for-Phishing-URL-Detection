2. FEATURE 1: DATA & PIPELINE VERSIONING WITH DVC
--------------------------------------------------------------------------------
A. The Problem It Solves:
   - Git is not designed to store large datasets or binary model files (.pkl).
   - Without versioned data, there is no reliable way to track which specific 
     dataset version produced which model version.

B. What Was Built:
   1. DVC Data Tracking:
      - Raw dataset (Network_Data/phisingData.csv) is version-controlled by DVC.
      - Git only tracks the lightweight pointer file (phisingData.csv.dvc) with MD5 hashes.
      - Actual data is pushed to DagsHub S3-compatible remote storage via `dvc push`.
   2. Reproducible Pipeline (dvc.yaml & dvc.lock):
      - 4-stage Directed Acyclic Graph (DAG):
        Data Ingestion -> Data Validation -> Data Transformation -> Model Training
      - Tracks code dependencies (deps) and stage outputs (outs).
      - Automatically skips unchanged stages to save compute time and resources.
      - Generates dvc.lock for deterministic reproducibility across environments.


3. FEATURE 2: CENTRALIZED EXPERIMENT TRACKING (DAGSHUB + MLFLOW)
--------------------------------------------------------------------------------
A. The Problem It Solves:

5. COMMONLY ASKED QUESTIONS & ANSWERS
--------------------------------------------------------------------------------
Q: Why not just store the dataset in GitHub or Google Drive?
A: GitHub has strict file size limits and repository bloat issues. Google Drive 
   lacks CLI automation, hash-based commit linking, and pipeline dependency tracking. 
   DVC links data directly to Git commits.

Q: What happens if raw data changes in production?
A: We run `dvc add Network_Data/phisingData.csv` followed by `dvc repro`. DVC detects 
   the updated dataset hash and automatically triggers all downstream stages.

Q: Why DagsHub instead of hosting MLflow manually on AWS EC2?
A: DagsHub offers zero-maintenance managed MLflow, Git integration, and S3-compatible 
   DVC storage in one unified platform, eliminating cloud setup overhead.
